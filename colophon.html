Things that look like JavaScript and aren't

Most of these needed a library, or at least a script, for the bulk of the period this site covers. Each one is now a browser feature. That is the third pattern on the lineage page in action: what the platform absorbs, the libraries stop needing to do.

Animated page transitions

once: Turbolinks, an SPA router

Navigate between chapters in a recent browser and the pages cross-fade. That's one CSS rule, @view-transition { navigation: auto; }. These are full, separate page loads, animated by the browser.

The reading progress bar

once: a scroll event listener

The yellow bar across the top is a CSS animation whose timeline is the scroll position instead of a clock: animation-timeline: scroll(). Browsers without support simply don't show it.

The timeline filter

once: jQuery, then a state library

The filter on the front page is a group of radio inputs. One selector does the work: body:has(#f-lib:checked) .timeline li:not(.lib) { display: none; }. The state lives in the form control, which is where jQuery apps kept it and where chapter 2 said it shouldn't be. For one filter, it's fine.

The popover in the header

once: Bootstrap's modal plugin

The "JS shipped" button has a popovertarget attribute, and the panel has a popover attribute. The browser handles opening, light dismiss, the Escape key, focus and the top layer.

Everything else

once: assorted plugins

Collapsible sections are <details>. Highlighting the entry you jumped to is :target. Smooth scrolling is scroll-behavior. The sticky header is position: sticky. Dark mode follows your system through prefers-color-scheme. Motion is reduced if you've asked your system for that.

What this proves, and what it doesn't

It proves a content site, which is what this is, needs no JavaScript in 2026, and that several effects once considered "app-like" are now plain CSS.

It doesn't prove the frameworks were a mistake. This site has no user accounts, no data that changes, no editing, and no state more complex than one filter. Nobody should build a spreadsheet or a chat client this way. The frameworks in this history exist because people were building things much harder than a nine-page essay.

The fair conclusion is the one chapter 5 reaches: match the tool to the page. For this page, the right amount of JavaScript was none.

A note on accuracy

Dates are first public releases unless stated, and several projects have more than one defensible date. "Who inspired whom" is drawn from what the authors themselves have said in talks, posts and release notes, simplified to fit. Framework histories are contested by the people who lived them. If you were there and remember it differently, you may well be right.
