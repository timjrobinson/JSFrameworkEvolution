Loops: ideas that came back

Have framework designs gone in circles? Yes, at least nine times. Whether that's a circle or a spiral depends on whether the second visit was better than the first. Usually it was.

The pattern is consistent. An idea is tried early and abandoned, generally for a practical reason and not because it was wrong: the browsers were too slow, the language too weak, the tooling missing. The industry moves to an alternative and pushes it until its own costs become unbearable. Then someone revisits the original idea with the practical obstacle removed.

Rendering goes back to the server

  1. Server renders pages 1995
  2. Client renders everything 2010
  3. Server, then client again 2016
  4. Server renders pages 2021

PHP and Rails assembled HTML on the server. The SPA era moved all of that into the browser and reduced the server to a JSON API. Meta-frameworks brought server rendering back but kept the full client app, so the work was done twice. Astro, Server Components and htmx now treat the server as the primary renderer again.

Circle or spiral? Spiral. A 2005 PHP page and a 2025 server component both query a database and emit markup. The modern one shares a component model with the interactive parts and can update in place without a full reload.

Observables, abandoned and then rebuilt as signals

  1. Knockout observables 2010
  2. Dirty checking 2010
  3. Virtual DOM diffing 2013
  4. Signals 2022

This is the cleanest loop in the history. Knockout tracked exactly which pieces of UI depended on which data. The industry preferred approaches that didn't track at all: re-check everything (AngularJS) or re-render everything and diff (React). Those were simpler to reason about. They also scaled with the size of the UI and not the size of the change. Signals are Knockout's model with the syntax and consistency problems solved.

Circle or spiral? Spiral, and the authors say so. Solid's creator has described his work explicitly as returning to Knockout with what was learned since.

HTML over the wire

  1. Ajax returns HTML fragments 2005
  2. Ajax returns JSON 2010
  3. Requests return HTML fragments 2020

The X in Ajax stood for XML, and in practice early Ajax mostly fetched ready-made HTML and inserted it. Rails had helpers for exactly this in 2005. The MVC era decided that servers should send pure data and clients should own all rendering. htmx and Hotwire reverse that decision. And Server Components, viewed from a distance, are a very sophisticated way to send rendered UI over the wire.

Circle or spiral? Nearly a circle. htmx's own author describes it as completing an old idea, not inventing a new one.

Mixing markup and logic

  1. PHP: code in HTML 1995
  2. Strict separation 2005
  3. JSX: HTML in code 2013
  4. SQL in components 2023

Early PHP interleaved database queries, logic and markup in one file. The reaction, "separation of concerns", produced unobtrusive JavaScript and logic-less templates. React argued the separation was artificial and put markup back in code. Server components finished the journey. When a 2023 conference demo showed an SQL query inside a form handler inside a component, half the audience saw the future and the other half saw 2004.

Circle or spiral? Spiral. The old problem was never co-location. It was the absence of components, scoping and escaping. Those now exist.

Two-way binding

  1. Two-way by default 2010
  2. One-way only 2013
  3. Two-way as opt-in sugar 2016+

Knockout and AngularJS made two-way binding their headline feature. React declared it harmful, because when anything can write to anything, tracing a change is hopeless. But writing a value prop and a change handler for every form input is tedious, so it came back in limited form: Vue's v-model, Svelte's bind:, Angular's model().

Circle or spiral? Spiral. The modern versions are shorthand for a one-way flow plus an event, scoped to one component boundary. The convenience returned without the app-wide tangle.

The compiler

  1. GWT: compile everything 2006
  2. "It's just JavaScript" 2013
  3. The framework is a compiler 2016–25

GWT treated JavaScript as an output format, and the community rejected that. For years "it's just JavaScript" was React's selling point against template-based rivals. Yet JSX already needed a compiler, and after Svelte the pretence dropped. Svelte, Solid, Vue, Angular and Qwik all lean on compilation, and React now ships a compiler too.

Circle or spiral? Spiral. GWT replaced the language. Modern compilers keep you in JavaScript and TypeScript and optimise what you wrote.

Mutation

  1. Mutate freely 2006
  2. Never mutate 2015
  3. Mutate, but tracked 2020+

jQuery and Backbone code mutated objects directly. Redux made immutability doctrine: never change state, always return a new copy. That gave predictability and a great deal of spread-operator boilerplate. Then Immer let you write mutations that produce immutable results, and Vue 3 and Svelte 5 use Proxies so that todo.done = true is both a plain assignment and a tracked update.

Circle or spiral? Spiral. It looks like 2006 code. Underneath, every write is intercepted.

Batteries included

  1. Full toolkits: Dojo, YUI 2005
  2. Small libraries: jQuery, Backbone 2006–10
  3. Full frameworks: Angular, Ember 2010–12
  4. Just the view: React 2013
  5. Full meta-frameworks 2016+

This one is a pendulum, and it has swung at least four times. Complete toolkits feel heavy, so people move to small composable libraries. Assembling those becomes a job in itself, so people move to integrated frameworks. "JavaScript fatigue" in 2015 was the low point of one swing. Meta-frameworks were the swing back.

Circle or spiral? Mostly a circle. This is a genuine trade-off with no stable answer, so expect it to swing again.

Forms and links

  1. <form action> 1993
  2. preventDefault + fetch 2010
  3. <form action> 2021

The SPA era's first move in any form handler was event.preventDefault(): stop the browser doing what it does, then reimplement it with a fetch call, a loading flag and an error state. Remix pointed out that the browser's built-in behaviour was fine and should be enhanced, not replaced. React 19 then made <form action={fn}> a core feature. File-based routing is the same story for URLs: a file's path is its address, as in PHP.

Circle or spiral? Spiral, barely. Same element, same attribute, now with pending states and no full-page reload.

So is any of it progress?

Yes. The cynical reading, that the industry spent twenty years returning to PHP, misses what changed on each lap.

What each return had that the original lacked

A component model. The server rendering of 2005 had includes and partials. Today's has composable, typed components shared between server and client.

A language that grew up. Proxies made transparent reactivity possible. Modules, classes and async functions removed whole categories of library.

Compilers. Many of the early ideas failed on ergonomics. A compiler can now hide the awkward parts.

The choice itself. In 2005 you rendered on the server because nothing else was possible. Now it's a decision, made per page or per component.

Why the loops happen at all

Each generation of developers meets the previous generation's solution without having felt the problem it solved. To someone who started in 2016, an SPA with a JSON API was simply how websites worked, and its costs were the only visible thing about it. The server-rendered alternative looked fresh.

There's also a structural reason. Most of these are real trade-offs: server versus client, explicit versus automatic, integrated versus composable. A trade-off has no permanent answer. As hardware, networks and the kinds of sites people build change, the best point on the curve moves, and the industry overshoots it in both directions.

What a prediction would look like

If the pattern holds, the next reversal will come from wherever today's consensus is paying the most. Two candidates stand out. The first is the complexity of the server/client boundary in the current meta-frameworks, which invites a swing back toward something simpler. The second is local-first software, where data lives on the device and syncs in the background. That would move state back to the client, and it would look a lot like Meteor in 2012.
