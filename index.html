1995 – 2026 · thirty years · roughly one new framework per week

A history of JavaScript frameworks, told without any JavaScript.

Every framework on this site was built because its author was annoyed by the previous one. This is the story of who was annoyed by what, what they built instead, what that got right, and what annoyed the next person.

The short version: we started by sending HTML from a server. We spent fifteen years moving everything into the browser. We have spent the last five moving most of it back. Along the way the same six or seven ideas were discovered, discarded, and rediscovered, each time with better tooling and a new name.

The long version is in five chapters, followed by two pages that cut across them: who inspired whom, and the ideas that came back around.

Five eras

  1. Taming the browser Browsers disagreed about everything. Libraries papered over the cracks. One of them won so completely that the browser absorbed it. 1995–2008 · Prototype, Dojo, YUI, MooTools, jQuery
  2. Apps need structure jQuery could change a page but couldn't organise an application. Four frameworks proposed four different answers. 2009–2012 · Backbone, Knockout, AngularJS, Ember
  3. Components and the virtual DOM Stop tracking what changed. Describe the whole UI, re-run it on every update, and let a diff work out the rest. 2013–2016 · React, Redux, Vue, Angular, Web Components
  4. Compilers and meta-frameworks The framework moves into the build step, and a second layer of frameworks grows on top to put rendering back on the server. 2016–2020 · Svelte, Next.js, Nuxt, hooks, Solid, Vite
  5. The server returns Ship less JavaScript. Render on the server. Update only what changed. It all sounds oddly familiar. 2020–now · RSC, Astro, Remix, Qwik, htmx, signals

Timeline

Filter by kind. The filter is a set of radio buttons and one CSS :has() selector.

  1. 1995JavaScript — written by Brendan Eich at Netscape in ten days, to make pages "come alive".
  2. 1999XMLHTTP — Microsoft ships it in IE5 for Outlook Web Access. Nobody notices for five years.
  3. 2004Gmail — proves a web page can behave like an application.
  4. 2004Dojo — the first serious toolkit: modules, widgets, deferreds.
  5. 2005"Ajax" — Jesse James Garrett names the technique. A gold rush follows.
  6. 2005Prototype — makes JavaScript feel like Ruby. Ships with Rails.
  7. 2006jQuery — select with CSS, chain, done. Wins the decade.
  8. 2006YUI and MooTools — the corporate toolkit and the elegant one.
  9. 2006GWT — Google compiles Java to JavaScript. The first "compiler as framework".
  10. 2007SproutCore — desktop-style apps in the browser, backed by Apple.
  11. 2009Node.js — JavaScript leaves the browser. npm follows in 2010, and tooling changes forever.
  12. 2010Knockout — observables and declarative bindings. Keep an eye on this one.
  13. 2010Backbone — models, views, a router, and very little else.
  14. 2010AngularJS — HTML extended with directives, two-way binding, dependency injection.
  15. 2011pjax — fetch HTML, swap a fragment, update the URL. Turbolinks follows in 2012.
  16. 2011Ember — SproutCore 2.0, renamed. Conventions, a real router, and a CLI.
  17. 2012Meteor — one language, both sides, live data. A decade early.
  18. 2012TypeScript, webpack and Elm — types, bundling, and a pure functional architecture.
  19. 2013React — "rethinking best practices". Booed at first, then copied by everyone.
  20. 2013Polymer — Google's bet that components should be a browser feature.
  21. 2014Vue — the parts of Angular one person liked, without the rest.
  22. 2014Flux — data flows one way. Angular 2 is announced, incompatible with Angular 1.
  23. 2015Redux and Preact — Elm's architecture in JavaScript; React in 3 kB.
  24. 2015ES2015 — classes, modules, arrow functions, promises. Babel makes it usable today.
  25. 2016Angular 2 — a full rewrite in TypeScript. Same name, different framework.
  26. 2016Svelte — the framework that compiles itself away.
  27. 2016Next.js and Nuxt — server rendering returns as a framework on top of a framework.
  28. 2018Solid — Knockout's reactivity with React's JSX and no virtual DOM.
  29. 2019React Hooks — classes out, functions in. Every other framework responds.
  30. 2019Alpine.js — "jQuery for the modern web": behaviour sprinkled into attributes.
  31. 2020Vite — native ES modules in dev. Within three years, nearly everyone's build tool.
  32. 2020htmx and Hotwire — hypermedia strikes back.
  33. 2020React Server Components announced — components that never reach the browser.
  34. 2021Astro, Remix, Qwik — three different ways to ship less JavaScript.
  35. 2022Signals go mainstream — Preact adopts them; Angular, Svelte and Vue follow.
  36. 2023Next.js App Router — server components become the default for new React apps.
  37. 2024Svelte 5 and React 19 — runes and server actions. A signals proposal reaches TC39.
  38. 2025React Compiler — React concedes that a compiler should do the memoising.
